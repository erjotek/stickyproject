## 2024-05-30 - Fix Log Forging / Log Injection Vulnerability
**Vulnerability:** Several logs (`StickyHeaderComponent.kt` tracking mimeTypes, `PinnedFoldersSettings.kt` and `PathValidator.kt` tracking file paths) logged external or user inputs directly via String template injection without sanitizing CRLF `\n` and `\r` characters.
**Learning:** Even internal settings, file paths, and MIME types coming from system clipboards can be tampered with by an attacker to forge log entries or obscure traces.
**Prevention:** Always use the `PathValidator.sanitizeForLog()` utility function when passing external, user-supplied, or potentially tampered strings to `LOG.warn`, `LOG.error`, or `LOG.info`.
## 2024-05-31 - Fix HTML Injection in Swing TableCellRenderer
**Vulnerability:** Swing components like `JLabel` (used by default in `DefaultTableCellRenderer`) automatically interpret and render strings starting with `<html>` as HTML. This can lead to HTML Injection/XSS in desktop applications, allowing UI spoofing or unauthorized network requests via `<img>` tags if malicious paths or settings are displayed.
**Learning:** Even in desktop IDE plugins, user-provided or external strings (like file paths or descriptions) displayed in tables or lists are vulnerable to injection attacks if the underlying Swing component's default HTML rendering is not disabled.
**Prevention:** Always use `(comp as? javax.swing.JComponent)?.putClientProperty("html.disable", true)` when overriding cell renderers (like `DefaultTableCellRenderer` or `ListCellRenderer`) to explicitly disable HTML rendering for text that may contain unvalidated or external input.
